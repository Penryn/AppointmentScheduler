# AppointmentScheduler 缺陷报告与改进记录

## BUG-001 并发重复预约风险

- 严重级别：高
- 模块：预约创建
- 现象：两个客户同时选择同一服务商同一开始时间时，服务层可用性判断存在竞争窗口。
- 风险：如果只依赖服务层先查后写，可能出现重复预约。
- 当前处理：数据库迁移 `V4__add_appointment_booking_guards.sql` 增加了 `(id_provider, start)` 和 `(id_customer, start)` 唯一约束。
- 新增验证：`AppointmentConcurrentBookingIT` 验证并发创建同一服务商同一时段时最终只保存一条记录。
- 后续建议：将数据库约束异常转换为用户可读的预约失败提示。

## BUG-002 ID 篡改访问风险

- 严重级别：高
- 模块：预约详情、日历接口、客户资料
- 现象：用户可能通过修改 URL 中的用户 ID 或预约 ID 尝试访问他人数据。
- 当前处理：服务层使用 `@PreAuthorize` 和 `@PostAuthorize` 限制客户、服务商、管理员的数据访问范围。
- 新增验证：补充客户访问他人预约详情和日历接口的负向安全用例。
- 后续建议：统一为越权访问记录安全审计日志。

## BUG-003 Ajax 接口契约漂移风险

- 严重级别：中
- 模块：Ajax 日历、可用时间、通知计数
- 现象：前端依赖固定 JSON 字段，如果后端重构时字段名或响应类型变化，页面可能静默失败。
- 当前处理：MockMvc 契约测试断言 `workId`、`providerId`、`start`、`end` 和 JSON 数组结构。
- 后续建议：为错误响应建立统一结构，例如 `code`、`message`、`traceId`。

## BUG-004 预约边界时间缺陷风险

- 严重级别：中
- 模块：可用时间计算
- 现象：预约刚好等于工作结束时间、跨休息时间、服务时长超过可用时段时容易出现边界错误。
- 当前处理：`AppointmentAvailabilityTest` 覆盖可用时段切分、休息时间排除、已有预约排除和边界值。
- 后续建议：增加参数化测试，覆盖更多工作时长组合。

## BUG-005 测试环境资源依赖风险

- 严重级别：中
- 模块：集成测试、UI 测试
- 现象：Testcontainers、Selenium 和 Playwright 依赖 Docker/浏览器环境，资源不足时可能失败。
- 当前处理：README 已说明 Docker、Node.js 和浏览器依赖。
- 后续建议：CI 中拆分单元测试、集成测试、UI 测试和性能测试阶段，避免互相影响。
